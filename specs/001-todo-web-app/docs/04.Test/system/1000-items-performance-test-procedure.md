# 1,000件性能回帰テスト 手順書

## 1. 目的
T044 の検証として、1,000件データ条件で以下操作の性能を回帰確認する。

- 一覧表示
- フィルタ
- ソート
- 完了切替

## 2. 対象環境
- Backend: `http://localhost:3000`
- Frontend: `http://localhost:5173`
- DB: SQLite (Prisma)
- 計測端末/OS/ブラウザは結果記録テンプレートに記入する。

## 3. 前提条件
- 依存関係がインストール済みである。
- DB 初期化が完了している。
- Backend / Frontend が起動している。
- テストデータとしてタスク 1,000件を準備できること。

推奨起動コマンド（リポジトリルート）:

```bash
npm install
npm run db:setup
```

Terminal 1:

```bash
cd backend
npm run dev
```

Terminal 2:

```bash
cd frontend
npm run dev
```

## 4. データ準備方針（1,000件）
- 総件数: 1,000件
- 状態: `todo` / `done` を混在
- 期限: `overdue` / `today` / `upcoming` / `none` を混在
- 優先度: `low` / `medium` / `high` を混在

例: 各状態・期限・優先度が偏らないよう均等に近い分布で投入する。

## 5. 計測ルール
- 各操作を最低 5 回実行し、平均値と最大値を記録する。
- 初回 1 回はウォームアップとして扱い、集計から除外してよい。
- 計測は同一条件（同一端末・同一ブラウザ・同一ネットワーク）で行う。
- 実測値は ms 単位で記録する。

## 6. 操作別手順

### 6.1 一覧表示
1. フィルタを `すべて` に戻す。
2. ブラウザをリロードする。
3. 一覧が描画完了するまでの時間を計測する。
4. 5 回以上繰り返す。

### 6.2 フィルタ
1. 期限フィルタで `本日期限` を選択する。
2. 結果が反映されるまでの時間を計測する。
3. 状態フィルタ `未完了` も組み合わせて計測する。
4. 5 回以上繰り返す。

### 6.3 ソート
1. 並び順を `期限が近い順`（`dueDate asc`）に変更する。
2. 表示更新完了までの時間を計測する。
3. `優先度が高い順` でも同様に計測する。
4. 5 回以上繰り返す。

### 6.4 完了切替
1. 一覧から `todo` タスクを1件選ぶ。
2. `完了にする` を実行し、表示反映までを計測する。
3. 同一タスクで `未完了に戻す` も計測する。
4. 5 回以上繰り返す。

## 7. 判定基準（暫定）
- `plan.md` 記載の性能目標を基準とする。
  - 参考: list query P95 < 200ms（1,000件条件）
- 目標を満たせば `Pass`、超過すれば `Fail` と判定する。

## 8. 記録
- 実測結果は `1000-items-performance-result-template.md` をコピーして記録する。
